# GC, Capacity, and Project Churn QA — 2026-10-25

Real Cargo builds passed cold oversized-member collection, active-member protection,
crash recovery, admission under an impossible free-space reserve, and 240 project
switches. A warm-growth defect bypassed both the warning and automatic collection:
[#109](https://github.com/r4ai/buildq/issues/109).

## Environment

- buildq `3a9e793108ddf1c3bebbd4d1af87cacf0b7ff79f`
- Linux x86_64, Rust/Cargo 1.89.0, 4-CPU quota, 16 GiB memory limit
- Dedicated `/tmp` tmpfs cache, 24 local standard-library-only Git repositories
- Two slots, one Cargo compiler job, inline automatic GC, dedupe disabled
- 64 MiB retention budget during churn; 8 MiB generated payload per build

The suite ran from 04:24:54 to 04:26:52 UTC (13:24:54–13:26:52 JST).
Its build timings are descriptive observations during shared-host QA, not an
isolated throughput benchmark. These small fixtures exercise the real Cargo,
pool, queue and collector paths; they are not large OSS compilations.

## Results

| Scenario | Observed behavior |
| --- | --- |
| 64 MiB payload, 32 MiB budget, twice from cold | Warned about the oversized completed member; inline GC evicted it; reported total returned to zero |
| Warm 1 MiB payload → 64 MiB within 60 seconds | No oversize warning; cached total remained below budget while actual member was over budget (#109) |
| Active 8 MiB payload, manual GC with 1 MiB budget | Member protected; payload SHA-256 unchanged; JSON explicitly reported busy overflow |
| SIGKILL of active outer buildq | Lease released; subsequent GC reclaimed the member |
| `min_free` above actual volume free bytes | Exit 125 with `pooled build refused` before Cargo started |
| 24 repositories, 240 alternating builds | All succeeded; refreshed managed usage stayed at or below 52,690,944 bytes against a 67,108,864-byte budget |
| Metadata aged by 30 days | Three retained idle members removed; managed usage returned to zero |

The churn's median individual build duration was 0.394 seconds. Retained lock
inodes and small pool metadata survived eviction by design; after the aging pass
25 pool directories and 50 lock files remained, with 106,496 bytes in the harness's
path-based allocated-file sum. The harness `footprint()` sums paths and can count
hardlink aliases more than once; use the buildq inventory's allocated accounting
for the retention-budget comparisons.

The 30-day check changes metadata timestamps. It does **not** establish 30 days
of continuous operation. Multi-day endurance remains tracked in
[#38](https://github.com/r4ai/buildq/issues/38).

## Warm Growth Reproduction

The independent release-binary reproduction returned:

```json
{
  "budget": 33554432,
  "cached_total": 9875456,
  "refreshed_total": 75997184,
  "warning": false,
  "manual_gc_freed": 75997184,
  "manual_gc_after": 0
}
```

`completed_member_warning` retains a size estimate for 60 seconds, including
across builds that add output. The recent-under-budget automatic-GC fast path
then uses the estimate. Cold overflow works; immediate warm growth is the failing
boundary. A manual refreshed inventory and foreground GC correctly see and
reclaim the extra bytes.

## Deferred Collection After Contention

The real Bevy pressure run completed all programs correctly but retained an idle
oversized member after concurrent collectors had reported busy protection.
A deterministic small control held `gc.lock` while a fresh Cargo build generated
a 64 MiB payload under a 32 MiB budget. After lock release, its idle cache stayed
at 75,849,728 bytes, with a fresh size estimate and no trash. Manual GC reclaimed
the entire amount. This is independent of #109's size TTL.

The control establishes that a skipped post-job request has no deferred retry;
it does not prove the exact Bevy collector interleaving. The budget is documented
as soft and manual retry works. The automatic retry/reliability improvement is
tracked as [#117](https://github.com/r4ai/buildq/issues/117).

## Reproduction and Evidence

Activate Rust, build buildq at the tested revision, then run from the repository:

```sh
python3 scripts/qa-2026-10-25/gc/run.py \
  --root /tmp/buildq-gc-new --out /tmp/buildq-gc-evidence \
  --buildq "$PWD/target/debug/buildq" --cycles 240 --repos 24
python3 scripts/qa-2026-10-25/gc/warm-growth.py "$PWD/target/release/buildq"
```

The first root must not exist. Both runners use generated local repositories and
offline Cargo. The full suite retains its root for inspection; the focused repro
removes only its own temporary directory.
