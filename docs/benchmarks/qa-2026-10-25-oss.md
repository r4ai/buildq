# Real OSS QA — 2026-10-25

Real Cargo builds and executable correctness checks against local copies of Tokio,
ripgrep, and rust-analyzer, using buildq `3a9e793` and the native Cargo backend.
All edits remain inside the QA clones. No upstream issue, PR, or push is involved.

## Scenarios and Correctness Oracle

The [harness](../../scripts/qa-2026-10-25/oss/run.py) adds a small public marker
function to an existing library and reads that marker from a real executable.
Two Git worktrees contain `AAA` and `BBB`, with equal source lengths and equal
source mtimes set to September 2020. Correct stdout is checked on every probe.

Tokio uses `full` features and runs 64 asynchronous tasks on two runtime threads.
The probe waits for all tasks and checks their sum before printing the marker.
ripgrep builds the complete `rg` executable and its local workspace dependencies;
an environment-gated probe prints a marker from the `grep` path dependency.
Its normal CLI behavior remains available for upstream integration tests.
rust-analyzer builds its real `syntax` library, parses 1,000 Rust functions, and
checks that the syntax tree reproduces the exact source text before reading the
marker. Its parser and syntax library tests also run through buildq.

Elapsed time includes queueing, Cargo, executable staging, and probe execution.
It excludes dependency downloads. These are individual observations rather than
a statistically repeated performance study. Other QA experiments share this
machine; known overlapping observations are excluded from performance comparisons.

The same-worktree edits test content-based invalidation without relying on the

The eight-request batch included creation of additional cold pool members. Its

### Temporary Directory Control

ripgrep's `feature::f1414_no_require_git` expects its temporary directory to have
no Git ancestor. This execution sandbox creates synthetic read-only `.git`
directories at `/tmp/.git` and `/workspace/.git`. Consequently, ripgrep correctly
applies `.gitignore` in the default temporary directory, and that test's expected
output differs. Running the existing test executable directly reproduces the
same failure, without buildq.

With the narrowly granted writable directory
`TMPDIR=/dev/shm/buildq-qa-ripgrep-tests`, the test passes directly and through
`buildq cargo test -- --exact feature::f1414_no_require_git`. The buildq control
selects `m1` with “no source differences”; Cargo reports a 0.06 s warm test
profile. This is an environmental test-precondition failure, not a buildq defect.
The original whole-suite failure remains in the evidence; a clean full-suite
rerun in the isolated temporary directory was not performed.

## Pool Affinity Observation

Although `cache.max_members = 2`, alternating serial requests only creates `m0`.
On every source-root change, buildq correctly invalidates all local workspace
packages to avoid reusing absolute paths or build-script outputs from the other
worktree. In this workload, Tokio invalidates twelve local workspace packages and
ripgrep invalidates ten. Registry dependencies remain reusable.

Consequently, a warm cache in another worktree still costs several seconds,
while an unchanged same-worktree request completes in about 0.1–0.2 seconds.
This is a measured pool-selection tradeoff, not a stale-artifact failure.
The capacity/affinity improvement is tracked in
[issue #113](https://github.com/r4ai/buildq/issues/113).

## Reproduction

Build buildq, put the chosen Rust toolchain on `PATH`, and choose a new local
measurement directory. The harness never writes to an upstream remote.

```sh
python scripts/qa-2026-10-25/oss/run.py --root /tmp/buildq-oss-qa --phase prepare
```

Fetch dependencies once in both clones before timing:

```sh
(cd /tmp/buildq-oss-qa/tokio && cargo fetch --locked)
(cd /tmp/buildq-oss-qa/ripgrep && cargo fetch --locked)
python scripts/qa-2026-10-25/oss/run.py --root /tmp/buildq-oss-qa --phase cold
python scripts/qa-2026-10-25/oss/run.py --root /tmp/buildq-oss-qa --phase switch
python scripts/qa-2026-10-25/oss/run.py --root /tmp/buildq-oss-qa --phase edits
python scripts/qa-2026-10-25/oss/run.py --root /tmp/buildq-oss-qa --phase recovery
python scripts/qa-2026-10-25/oss/run.py --root /tmp/buildq-oss-qa --phase parallel
python scripts/qa-2026-10-25/oss/run.py --root /tmp/buildq-oss-qa --phase tests
python scripts/qa-2026-10-25/oss/run.py --root /tmp/buildq-oss-qa --phase prepare-ra
(cd /tmp/buildq-oss-qa/rust-analyzer && cargo fetch --locked)
python scripts/qa-2026-10-25/oss/run.py --root /tmp/buildq-oss-qa --phase ra
```

Pass `--buildq /absolute/path/to/buildq` when the binary is elsewhere.
Run one phase at a time on an otherwise idle machine for interpretable timings.
The harness writes stdout, stderr, and JSONL records beneath `ROOT/results`.
Reruns receive distinct labels so earlier evidence is preserved.
Use a temporary directory without a Git ancestor for ripgrep's integration
tests. In this sandbox that required a dedicated extra writable path.

Checked-in [raw results](../../scripts/qa-2026-10-25/oss/results/results.jsonl),
[summary](../../scripts/qa-2026-10-25/oss/results/summary.json), and representative
stdout/stderr logs preserve both expected failures and successful controls.
The harness passed Python compilation, Ruff lint, and Ruff formatting checks.

## Scope

These runs exercise actual upstream source and dependency graphs with small local
development edits. They do not establish that every feature, platform, integration
test, or workspace package of each repository builds. Linux measurements do not
validate macOS/Windows behavior or reflink deduplication. Tokio and ripgrep are
smaller source trees than rust-analyzer; popularity is not used as a proxy for
source-tree or artifact size.
