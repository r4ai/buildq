# Runtime QA and mr-boxington Benchmarks — 2026-10-25

This campaign exercised buildq at `3a9e793108ddf1c3bebbd4d1af87cacf0b7ff79f`
with real Cargo, real mr-boxington 1.27.0, pinned OSS revisions, parallel
worktrees, cancellation, cache churn and storage pressure. It found four
reproducible runtime bugs, six measured usability/performance opportunities,
and an existing development-check failure.
The PR adds reports, reproducers and recorded evidence; it does not patch the
runtime defects or change the default backend.

Wrong-output reproduction is confirmed for native Cargo. mbx also left live
descendants after SIGTERM, but its surviving Cargo process retained Cargo's
target lock in that particular control, preventing the demonstrated overwrite.
SIGKILL watchdog controls and automatic free-space-pressure termination passed.
The distinction matters: a passing cancellation mechanism does not cover every
way a job can end.

## Environment and Scope

- Linux x86_64 managed container: 4 CPU quota, 16 GiB memory limit, no swap
- `/workspace` overlay volume: approximately 32 GiB; `/tmp` tmpfs for small pressure fixtures
- Rust/Cargo 1.89.0; additional real-mbx functional checks on Rust 1.91.1
- Rebuilt debug and release buildq binaries from the tested SHA; the preinstalled binary was older
- Real mbx v1.27.0 release archive verified against its SHA256SUMS
- Per-scenario queue/cache/store directories; explicit compiler-job and slot limits

The workload sources were Bevy 0.16.1 (PBR/PNG/multithreading fixture),
Tokio 1.48.0, ripgrep 14.1.1 and rust-analyzer 2025-07-28. Tokio and ripgrep
were built as real local OSS worktrees with marker changes in workspace crates.
rust-analyzer covered syntax/parser crates and a local parser probe; it was not
a build of every IDE component. Exact revisions, source sizes and locks are in
the [OSS provenance](../../scripts/qa-2026-10-25/oss/provenance.json).
No issues, commits, pushes or PRs were sent to the OSS fixture repositories.

Subagent concurrency was reduced to the requested maximum of three when that
limit was specified. Distinct worker caches prevented cross-test eviction.
Early measurements shared CPU/filesystem resources; their timings are explicitly
descriptive. The comparison's second traversal was reserved for the heavy benchmark.

## Bevy Comparison

Detailed results and methodology: [six-worktree comparison](qa-2026-10-25-bevy.md).
The workload submits six builds simultaneously. Native Cargo uses six independent
targets; buildq limits admission and pools targets; mbx restores compiler outputs;
combined modes use the new native `backend="mbx"` launcher with two or four slots.

Both tools' automatic collectors are disabled for the controlled retention
comparison. A separate two-wave run enables both collectors under tight budgets;
that result must not be inferred from the GC-disabled throughput numbers.

## Interpretation and Limits

The successful runs demonstrate useful integration coverage, not universal
compatibility with all huge Rust projects. Repeated-worktree reuse still has
meaningful invalidation costs, and mbx adds a separate store/private state.
Combined accounting and collector coordination remain tracked in
[#105](https://github.com/r4ai/buildq/issues/105) and
[#106](https://github.com/r4ai/buildq/issues/106).

Neither available filesystem supports the tested reflink operation. The dedupe
probes therefore establish content classification, locking, safe unsupported
behavior and metadata cost. They do not measure physical block-sharing savings
or validate APFS clone-and-relink crash behavior. mbx hardlinks are measured
separately using a single device/inode set across targets and its store.

The GC churn completed 240 real builds; the 30-day retention check explicitly
aged metadata. Neither is a multi-day soak. The missing multi-day evidence is
still tracked in [#38](https://github.com/r4ai/buildq/issues/38).
The storage-pressure fixtures raise a free-space reserve while writing bounded
payloads; they do not intentionally fill the machine to actual ENOSPC.
Windows, macOS, cross-user cache access and real remote SSH were not exercised.

## Reproduction

All new runners and evidence are under
[`scripts/qa-2026-10-25/`](../../scripts/qa-2026-10-25/).
Use the per-report commands, fresh disposable roots, the pinned toolchains and
the real mbx binary. Dependencies must be fetched before offline Cargo timings.
The Bevy fixture lockfile is included. Python benchmark dependencies and tools
are pinned by `scripts/uv.lock`; use `uv sync --project scripts --locked`.

Reports include expected failures, environment-specific controls and descriptive
timing caveats. They distinguish content duplicates, reported estimates, file
allocation counted once per inode, and measured process RSS.
