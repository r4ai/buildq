# Documentation & README Writing Skill

リポジトリの `README` および `docs/` 配下のドキュメントを作成・更新する際は、以下の構成・文体・フォーマット規約に従うこと。

## 1. ドキュメント構成とファイル分割

### README の論理フロー
初見の読者が「何のリポジトリか」を最短で理解し、納得感を持てる順序で構成する。
不要な情報は引き算して削除し、本質的に必要な情報のみを残す。

1. **冒頭の一言要約**
   - タイトルと言語切替リンクの直下に、具体的に何をするツールなのかを1文（体言止め）で明示
2. **解決する課題・主な機能・パフォーマンス**
   - **解決する課題**: 既存のやり方で何が問題なのかを短い箇条書きで提示
   - **全体像の図解**: Mermaid フローチャートで仕組みの全体像を図示
   - **主な機能**: 何をするのかを「太字見出し＋短いネスト箇条書き」で整理
   - **パフォーマンス比較**: 従来手法との比較表（実測値・定量的指標）を提示
3. **インストール方法**
   - リポジトリ公開前提で、`git clone` なしで導入できる手順（例: `cargo install --git https://github.com/...`）を記載
4. **使い方**
   - 基本的な使い方、CLI コマンド一覧表、最小限の `config.toml` 例を記載
5. **技術的な仕組み（概要）**
   - Mermaid 図と3点程度の要点リストで、なぜ速く安全に動くのかを簡潔に説明
6. **詳細ドキュメントへのリンク・ライセンス**

### ドキュメントの分離と日英対応
- **アーキテクチャ詳細**: 内部構造・アルゴリズム・プロトコル・代替案比較・制限事項は `docs/architecture.md` / `docs/architecture.ja.md` に分離
- **開発者向け情報**: モジュール構成・テスト実行手順・マルチエージェント環境構築レシピ・環境変数一覧は `docs/development.md` / `docs/development.ja.md` に分離
- **日英両対応**:
  - `README.md` ⇔ `README.ja.md`
  - `docs/architecture.md` ⇔ `docs/architecture.ja.md`
  - `docs/development.md` ⇔ `docs/development.ja.md`
  - 各ファイルのタイトル直下に `English | [日本語](...)` の相互リンクを配置
- **見出しは常に英語で統一（日英共通）**:
  - 日本語ドキュメント（`*.ja.md`）であっても、見出し（`#`, `##`, `###` 等）は英語ドキュメントと完全に同一の英語表記にする
  - 見出しを英語で統一することで、日英間での構造対応が保たれ、セクションへのリンクアンカー（`#multi-agent-sandbox-recipe` 等）が共通化されてリンク切れや参照ズレを防ぐ
  - 本文のみを自然な日本語（である調）で記述する
- **Future Work の扱い**:
  - 未実装の課題や今後の展望（Next steps / Future work）はドキュメント内に書き連ねず、`gh issue create` で GitHub Issue（`## As-Is` / `## To-Be` 形式）として登録する

## 2. 文体・記述スタイル

- **である調で統一**
  - 日本語ドキュメントは「です・ます」を使わず、すべて「である調」で記述
- **1文を短く・適切な改行**
  - 1文を長くしすぎず、文単位・意味の区切れで適切に改行
- **箇条書きの簡潔化と体言止め**
  - 箇条書きの1項目は短く保ち、適宜**体言止め**にして簡潔にまとめる
  - 1項目が長くなる場合は、項目を分割するかサブ項目としてネストする
- **自明な句点（`。` / `.`）の省略**
  - 箇条書きの項目、表のセル、体言止めの文、見出し直下のキャッチコピー等では末尾の「。」（英語では `.`）を書かない

## 3. 改行とレイアウトの調整

- **不必要なセパレータ（`---`）の禁止**
  - 見出し（Heading: `#`, `##` 等）自体がセクションの明確な区切りとなるため、見出しの直前やセクション間に無駄に `---` を挿入しない（Frontmatter を除く）
- **表（テーブル）での手動改行**
  - 比較表（4列など）やコマンド表は表示幅が狭くなり、単語や括弧の途中で不自然に折り返されやすい
  - 数値と補足説明の境界（例: `` `11.2 秒`<br>（8 クレート再ビルド） ``）や、長い見出しの区切れに `<br>` を手動挿入して読みやすくする
- **箇条書きの折り返し防止**
  - 1行が長くなり自動折り返しが発生しそうな箇条書きは、2つのサブ項目に分ける

## 4. Mermaid 図のルール

- サポートされた図種（`flowchart TD` / `flowchart LR`, `sequenceDiagram` 等）のみを使用
- **HTML タグの禁止**: Mermaid のノードラベルやメッセージ内に `<br>` や `<pkg>`, `<i>` などの山括弧を含めない（HTML タグと誤認され表示崩れやパースエラーの原因になる）
- **特殊文字のクォート**: 括弧 `()` やスラッシュ `/` を含むラベルは必ずダブルクォートで囲む（例: `Node["ラベル (補足)"]`）
- **短いラベル**: ボックス内で文字が詰まらないよう、ノード内のテキストは短く簡潔にする
